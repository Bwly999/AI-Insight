# 11 · 内网扩展点

本平台的核心理念：**简单实现先跑，复杂能力由使用方在内网按接口实现**。以下四类扩展点均已定义统一接口契约，仓库仅提供接口与默认实现，**接入内网实现无需改动核心代码**。

## 11.1 扩展点总览

| 扩展点 | 接口 | 默认实现 | 使用方内网实现 |
|---|---|---|---|
| 推送通道 | `INotificationChannel` | `ConsoleNotifier`（打印） | Email / 企微 / 飞书 / 钉钉 / Telegram |
| 采集器 | `ICollector` | RSS / SearchApi / SearchCrawl / Playwright(预留) | 内部知识库 / 内网数据源 |
| LLM | Vercel AI SDK（非自研） | 内网 OpenAI 兼容地址 | 内网私有模型（改 baseURL） |
| 认证 | jose 解 JWT + 查库 | 外部 token 验证 | （登录服务使用方提供） |

## 11.2 推送通道扩展

### 接口
```ts
export interface NotificationPayload {
  userId: string; userName: string;
  reportId: string; issueNo: string;
  subject: string; summary: string;
  reportUrl: string; reportDeepJson: unknown;
  meta?: Record<string, unknown>;
}
export interface INotificationChannel {
  readonly channel: string;
  send(p: NotificationPayload): Promise<{ ok: boolean; error?: string }>;
}
```

### 默认实现
`ConsoleNotifier`（channel=`CONSOLE`）：仅 `console.log` 打印 payload，零依赖。

### 使用方接入示例
```ts
// 使用方内网代码
fastify.registerNotifier('WECOM', new WeComChannel({ webhook: process.env.WECOM_WEBHOOK }));
fastify.registerNotifier('EMAIL', new EmailChannel({ smtp: process.env.SMTP_HOST }));
```
注册后，delivery.worker 按 `subscription.channels` 自动调用，**核心代码零改动**。

### 管理端配置
- `/admin/channels`：查看已注册通道、配置密钥、连通性测试。
- 通道密钥加密存储。

## 11.3 采集器扩展

### 接口
```ts
export interface ICollector {
  readonly type: string;
  fetch(source: SourceConfig): Promise<RawItemInput[]>;
  health?(source: SourceConfig): Promise<{ ok: boolean; detail?: string }>;
}
```

### 默认实现
| type | 实现 | 状态 |
|---|---|---|
| `RSS` | RssCollector | 开箱即用 |
| `SEARCH_API` | SearchApiCollector | 开箱即用 |
| `SEARCH_CRAWL` | SearchCrawlCollector | 开箱即用 |
| `WEB_SCRAPER` | PlaywrightScraperCollector | 能力预留，深度后补 |

### 使用方接入示例
```ts
// 使用方内网代码：接入内部知识库
fastify.registerCollector('INTERNAL_KB', new InternalKbCollector({ endpoint: '...' }));
```
管理端新建数据源时 type 选 `INTERNAL_KB` + 填 config，调度自动调用。

## 11.4 LLM 扩展

LLM 不自研抽象，直接用 Vercel AI SDK。切换内网模型只需改 `llm.ts` 插件配置：

```ts
const provider = createOpenAI({
  baseURL: process.env.LLM_BASE_URL,   // 指向不同内网模型服务
  apiKey:  process.env.LLM_API_KEY,
});
fastify.decorate('llm', { chat: provider(process.env.LLM_MODEL) });
```

- 若内网模型服务提供 OpenAI 兼容 `/v1/chat/completions`，改 baseURL 即可。
- 若为自定义协议，可在 `llm.ts` 内写一个适配 `LanguageModel` 接口的包装。

## 11.5 认证扩展

- 登录服务由使用方提供（签发 JWT）。
- 后端 `auth.ts` 用 jose 解 JWT，**秘钥与解包逻辑留白**由使用方填。
- 角色由后端查库定（管理员可在管理端改 role）。

## 11.6 扩展原则

1. **接口先行**：所有扩展点定义在 `packages/shared-types`，前后端共享。
2. **注册即用**：Fastify `registerCollector` / `registerNotifier` 注册后自动被调度调用。
3. **零改核心**：使用方实现只需 (a) 实现接口 (b) 注册，不触碰 worker / 路由 / 数据模型。
4. **配置驱动**：管理端通过 type/channel + config 选择用哪个实现，运行时可切换。
