# 04 · 后端架构

后端基于 **Fastify + TypeScript**，采用 **plugin + decorate** 模式实现模块化与 SPI（无重 DI 容器）。

## 4.1 目录结构

```
apps/server/src/
├── plugins/                # Fastify 插件 = 模块
│   ├── auth.ts             # preHandler: 解 Bearer + jose 解 JWT + 查库定 role → request.user
│   ├── db.ts               # decorate('db', drizzle client)
│   ├── queue.ts            # decorate('queue', bullmq 实例)
│   ├── http-client.ts      # decorate('http', 带管理端配置代理的 undici 客户端)
│   ├── llm.ts              # decorate('llm', Vercel AI SDK 实例, baseURL 指内网)
│   ├── collectors.ts       # 【SPI】采集器注册表 + 默认实现
│   ├── notifiers.ts        # 【SPI】推送通道注册表 + ConsoleNotifier
│   └── scheduler.ts        # cron: 采集(全局) + 处理(全局) + 报告(按 schedule)
├── routes/
│   ├── auth/me.ts          # GET /auth/me 返回当前用户+角色（无登录接口）
│   ├── reports/            # 用户端: 本期/往期/详情
│   ├── subscriptions/      # 用户端: 订阅设置（领域+关键词+挂载到 schedule）
│   ├── feedback/           # 用户端: 反馈/收藏
│   ├── admin/sources/      # 管理端: 数据源 CRUD + 手动触发采集
│   ├── admin/categories/   # 管理端: 领域定义
│   ├── admin/schedules/    # 管理端: ReportSchedule（报告调度目标）+ cron 配置
│   ├── admin/cron/         # 管理端: 全局采集/处理 cron
│   ├── admin/proxy/        # 管理端: HTTP 代理配置
│   ├── admin/reports/      # 管理端: 报告查看/手动重推/事后纠错
│   ├── admin/users/        # 管理端: 用户 + 角色
│   └── admin/channels/     # 管理端: 通知通道配置 + 测试
├── workers/                # BullMQ worker（独立进程或同进程）
│   ├── collection.worker.ts
│   ├── processing.worker.ts
│   ├── report.worker.ts    # 按 ReportSchedule 触发，为该目标下所有用户裁剪组装
│   └── delivery.worker.ts
└── main.ts
```

## 4.2 插件层职责

| 插件 | decorate | 职责 |
|---|---|---|
| `auth.ts` | 注入 `request.user` | preHandler：解 Bearer token → jose 解 JWT → 查库定 role |
| `db.ts` | `fastify.db` | Drizzle client 单例 |
| `queue.ts` | `fastify.queue` | BullMQ 队列实例（collection/processing/report/delivery） |
| `http-client.ts` | `fastify.http` | 带管理端配置代理的 HTTP 客户端（undici/got） |
| `llm.ts` | `fastify.llm` | Vercel AI SDK 实例，baseURL 指内网 |
| `collectors.ts` | `fastify.collectors` + `registerCollector` | 采集器 SPI 注册表 |
| `notifiers.ts` | `fastify.notifiers` + `registerNotifier` | 推送通道 SPI 注册表 |
| `scheduler.ts` | — | 注册 cron：采集（全局）、处理（全局）、报告（按 schedule） |

## 4.3 路由层

### 用户端路由（需登录，USER/ADMIN 均可）
| 方法 | 路径 | 功能 |
|---|---|---|
| GET | `/auth/me` | 当前用户 + 角色 |
| GET | `/reports/current` | 本期报告（按用户订阅裁剪后的最新 Report） |
| GET | `/reports/archive` | 往期报告列表（按期） |

| POST | `/feedback` | 提交反馈/收藏（USEFUL/USELESS/COLLECT） |
| GET | `/feedback` | 我的反馈/收藏列表 |

## 4.4 Worker 层

四个 BullMQ 队列与对应 worker：

| 队列 | 触发 | 处理 |
|---|---|---|
| `collection-queue` | 全局采集 cron / 管理端手动 | 调 `ICollector.fetch` → 去重 → 落 RawItem |
| `processing-queue` | 全局处理 cron | AI 五阶段 → 落 Article 池 |
| `report-queue` | 各 ReportSchedule cron / 管理端手动 | 按订阅裁剪组装 → 落 Report(READY) |
| `delivery-queue` | Report READY 后 / 管理端重推 | 调 `INotificationChannel.send` → 落 NotificationLog |

- 所有 worker 支持指数退避重试、死信队列。
- worker 可作为独立进程部署，或与 API 同进程（小规模场景）。

## 4.5 SPI 注册机制

```ts
// collectors.ts
fastify.decorate('collectors', new Map<string, ICollector>());
fastify.decorate('registerCollector', (type, impl) => {
  fastify.collectors.set(type, impl);
});
// 启动时注册默认实现
fastify.registerCollector('RSS', new RssCollector(fastify.http));
fastify.registerCollector('SEARCH_API', new SearchApiCollector(fastify.http));
fastify.registerCollector('SEARCH_CRAWL', new SearchCrawlCollector(fastify.http));
fastify.registerCollector('WEB_SCRAPER', new PlaywrightScraperCollector()); // 预留

// notifiers.ts
fastify.decorate('notifiers', new Map<string, INotificationChannel>());
fastify.decorate('registerNotifier', (channel, impl) => {
  fastify.notifiers.set(channel, impl);
});
fastify.registerNotifier('CONSOLE', new ConsoleNotifier()); // 默认打印
```

调度时按 Source.type / Subscription.channels 查表调用，**核心代码无需改动**即可接入内网实现。
