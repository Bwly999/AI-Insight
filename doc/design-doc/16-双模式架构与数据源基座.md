## 1. 背景与目标

### 1.1 为什么需要两种模式

| 维度 | Mode 1 · 订阅推送 | Mode 2 · 主动洞察 |
|---|---|---|
| 触发方 | **系统**（cron 周期） | **用户**（一句意图）或定时巡更 |
| 数据范围 | 预采集的 `articles` 池（被动消费） | 按意图**动态调度**采集器 + 已有池（主动求证） |
| 处理深度 | 编辑流水线（去重/分类/摘要/热度/点评）固定五阶段 | **Agent 自主规划**：选 sensor、定 query、选 lens、迭代 |
| 产出 | 标准 Report（实体化存档，可推多通道） | Insight Report（带思考链 trace、可对比可回放） |
| 用户角色 | 读者 / 订阅者 | 分析师 / 探索者 |
| 成本可控度 | 由 cron 与窗口决定，**固定** | 由 Agent 预算（token / 步数 / 工具调用次数）决定，**必须可限** |
| 适合问题 | 「这周 AI 圈发生了什么」 | 「Claude Code 与 Cursor 在企业内网落地，谁的方案更成熟」 |

两个模式**共享同一套数据源基座、同一套原始项入库逻辑、同一套 Article 池**。差别仅在「谁来决定采集什么、谁来决定怎么分析」。

### 1.2 两个参考项目的定位

- **`ref/newsnow` → 数据源基座的「广度」**。提供 40+ 站点的现成采集配方（RSS / RSSHub / HTML 爬取 / JSON API 四种模式），是我们的 **源种子库 + 采集器实现样本**。它本身没有 Agent、没有报告、没有推送 —— 它负责「把全网热榜收齐」。
- **`ref/Signex` → Mode 2 的「思想原型」**。提供 Watch/Sensor/Lens/Vault 四概念 + 16+ sensor，但实现是 Python + Claude Code 个人 Agent。我们要**用 TS 改写 sensor、用 Pi Agent SDK 重做 Agent 运行时、加安全边界**，把它从「个人脚本」升级成「平台托管的多用户受控 Agent」。
- **Pi Agent SDK（`@mariozechner/pi-coding-agent` / `pi-gateway`）→ Mode 2 的运行时**。提供 ExtensionAPI（registerTool / registerCommand / hooks）、SKILL.md 三级渐进式加载、Tool Bridge、gateway 多会话调度。我们用它做受控 Agent，**而不是**直接把 Signex 的 Python 脚本搬过来。

### 1.3 核心目标

1. **一套采集器**同时服务两种模式：Mode 1 cron 调，Mode 2 Agent 调，零代码重复。
2. **newsnow 的源**能配置化导入（不写死代码）。
3. **Signex 的 sensor**用 TS 重写并归一为 `ICollector`。
4. **Mode 2 用 Pi Agent + 自定义工具 + MD 声明式 Skill**，强约束：工具白名单、token/步数/调用次数预算、审计 trace、出网经统一代理。
5. **安全**比 Signex 更严：Skill 热加载走 DB 版本表（带 audit），工具调用全部走平台受控通道（不让 Agent 直接 exec / fetch 外网），Agent 进程与主服务隔离。

## 2. 总体架构

```
                        ┌─────────────────────────────────────────────────┐
                        │                 数据源基座（共享）                  │
                        │  sources 表 + 4 类 ICollector + 指纹去重 + raw_items │
                        │  ┌──────────────────────────────────────────┐    │
   newsnow 源种子 ──►   │  │ RssCollector │ SearchApiCollector         │    │
   Signex sensor ──►    │  │ SearchCrawlCollector │ WebScraperCollector│    │
   管理端配置   ──►     │  └──────────────────────────────────────────┘    │
                        └───────────┬──────────────────────┬──────────────┘
                                    │ fetch                │ fetch
                       ┌────────────▼─────────┐   ┌────────▼───────────────┐
                       │   Mode 1 · 订阅推送    │   │  Mode 2 · 主动洞察       │
                       │  scheduler cron       │   │  Pi Agent Runtime       │
                       │   ↓                   │   │   ↓                     │
                       │  collection.worker    │   │  受控工具集（白名单）       │
                       │   ↓ raw_items         │   │   ├ collect(skill 选源)  │
                       │  processing.worker    │   │   ├ search(查询类 API)   │
                       │   ↓ articles 池       │   │   ├ extract(正文补全)    │
                       │  report.worker        │   │   ├ vault(沉淀库读写)    │
                       │   ↓ reports           │   │   └ finalize(产出报告)  │
                       │  delivery.worker      │   │   ↓                     │
                       │   ↓ 多通道             │   │  insight_session + trace │
                       └───────────────────────┘   └─────────────────────────┘
                                    │                           │
                                    └───────────┬───────────────┘
                                                ▼
                                   共享: articles / raw_items / vault
```

要点：
- 采集器是**唯一真源**。Mode 2 的 `collect` 工具内部就是调 `fastify.collectors.get(type).fetch(...)`，不会另写一套。
- Mode 2 产出**额外入库**：`insight_session`（一次会话）+ `agent_step`（每一步思考）+ `agent_tool_call`（每次工具调用）。这些是 Mode 1 没有的，用于审计与回放。
- 两种模式的最终产物都可以走 `reports` 实体化（Mode 2 报告 issueNo 用 `INS-` 前缀，Mode 1 用日期前缀）。

## 3. 数据源基座（融合 newsnow + Signex）

### 3.1 采集器分型（不变 4 类，新增 config 标准）

保留 [05-可插拔SPI设计](./05-可插拔SPI设计.md) §5.1 的 4 类 `ICollector`，但把 `SourceConfig.config: Record<string, unknown>` **按 type 标准化为 zod schema**，让管理端能自动生成表单、让源种子能用 JSON 灌库。

| type | 来源参考 | config 标准字段 |
|---|---|---|
| `RSS` | newsnow `defineRSSSource` / Signex `fetch-rss` / `fetch-arxiv` | `{ feedUrl, maxItems?, stripHtml? }` |
| `SEARCH_API` (mode=`list`) | newsnow JSON 接口（wallstreetcn / bilibili / aihot / v2ex）+ Signex `fetch-hacker-news`(Firebase) | `{ mode:'list', endpoint, method?, headers?, resultPath, fieldMap, maxResults? }` |
| `SEARCH_API` (mode=`query`) | Signex `fetch-tavily` / `fetch-brave` / `fetch-exa` | `{ mode:'query', endpoint, method, headers?, apiKeyRef, queryField, queryTemplate?, resultPath, fieldMap, days?, maxResults? }` |
| `SEARCH_CRAWL` | newsnow HTML 爬取（ithome / github-trending / hackernews / reddit-list） | `{ listUrl OR searchUrlTemplate, itemSelector, fieldSelectors:{title,url,date?}, maxResults? }` |
| `WEB_SCRAPER` | Signex `extract-content` | `{ bodyExtractor:'readability'\|'firecrawl', maxBytes?, selectors? }`（Phase 2 正文补全用） |

`fieldMap` 形态：`{ title:'data.list[*].title', url:'data.list[*].uri', publishedAt:'data.list[*].display_time', summary?'content_short' }`，用**点路径 + 末段 `[*]` 通配**（自研 30 行解析器，不引 JSONPath 依赖，覆盖参考项目全部用例）。

### 3.2 源元数据（学习 newsnow）

`sources` 表已有字段（code/name/type/config/enabled）足够承载。**额外约定** `config` 内可放非采集参数：
- `interval`：采集频率档（学习 newsnow `Time.{Realtime=2m, Fast=5m, Default=10m, Common=30m, Slow=1h}`）。Mode 1 的全局 cron 会按每个源的 interval 决定本轮是否拉它（避免每轮全量）。
- `category`：newsnow 风格的栏目归属（china/world/tech/finance）—— 给 Mode 1 默认裁剪用。
- `color` / `home`：管理端展示用（不参与采集逻辑）。

### 3.3 指纹去重（融合 Signex + newsnow）

| 策略 | 适用 | 算法 |
|---|---|---|
| URL 指纹（默认） | RSS / SEARCH_API / SEARCH_CRAWL | URL 归一化（去 fragment、sort query、去跟踪参 `utm_*`/`from`/`ref`）→ sha256 前 16 位 |
| 标题指纹（兜底） | URL 缺失或动态（部分搜索结果） | 标题去标点空格 → sha256 前 16 位 |
| (source, source_id) | Signex 风格 sensor 自带稳定 id | `sourceCode + '::' + sourceId` → sha256 前 16 位 |

`raw_items.fingerprint` 唯一约束 + insert 时 catch duplicate = 跳过。同时写 `dedupeKey` 记录是哪种策略命中（便于运营排查「为什么这条没入库」）。

### 3.4 源种子库（newsnow 改写为 config）

新建 `apps/server/src/seed/sources-seed.ts`，**不复制 newsnow 的 .ts 源文件**，而是把它们**翻译成 SourceConfig JSON**。优先挑内网可达 / 国内可达的 8–12 个作为默认种子：

| code | type | 来源原型 | 内网可达性 |
|---|---|---|---|
| `rss-solidot` | RSS | newsnow solidot (`/index.rss`) | 高 |
| `rss-aihot` | RSS | newsnow aihot (`/feed/all.xml`) | 高 |
| `rss-arxiv-csai` | RSS | Signex fetch-arxiv | 高（arxiv 镜像） |
| `crawl-ithome` | SEARCH_CRAWL | newsnow ithome 选择器 | 高 |
| `crawl-hackernews` | SEARCH_CRAWL | newsnow hackernews 选择器 | 中（需代理） |
| `crawl-github-trending` | SEARCH_CRAWL | Signex fetch-github-trending | 中（需代理） |
| `api-wallstreetcn-live` | SEARCH_API(list) | newsnow wallstreetcn | 高 |
| `api-bilibili-hot` | SEARCH_API(list) | newsnow bilibili | 高 |
| `api-v2ex-hot` | SEARCH_API(list) | Signex fetch-v2ex | 高 |
| `api-hackernews-firebase` | SEARCH_API(list) | Signex fetch-hacker-news | 中 |
| `search-tavily` | SEARCH_API(query) | Signex fetch-tavily | 需 key + 代理 |
| `search-brave` | SEARCH_API(query) | Signex fetch-brave | 需 key + 代理 |

种子用 `INSERT ... ON DUPLICATE KEY UPDATE` 灌入，管理端可禁用 / 改 / 删。

### 3.5 HTTP 客户端升级（吸收 newsnow `myFetch`）

`http-client.ts` 升级：
- 默认 UA：`Mozilla/5.0 ... aihinsight/0.1`（吸收 newsnow）。
- 默认超时：连接 15s / 头 30s / 体 30s（已有）。
- 默认重试：3 次指数退避（新增，吸收 newsnow `retry:3`）。
- **代理**：管理端写入后动态 `setGlobalDispatcher(new ProxyAgent(url))`（B7）。
- **Agent 出网也走这里**：Mode 2 工具的所有出网强制经 `fastify.http`，不允许 Agent 自带 fetch 直连（安全）。

## 5. Mode 2 · 主动洞察（新增）

### 5.1 概念映射（Signex → 我们）

| Signex | 我们（落地形态） | 备注 |
|---|---|---|
| Watch（监控哨） | `insight_session`（一次会话一条）+ 可选「保存为订阅」转 Mode 1 | Signex 是长期 watch；我们默认一次性，可转长期 |
| Sensor（探针） | `ICollector` 实例（统一基座，非每源一个 skill） | **不**照搬 Signex「每 sensor 一个 skill」，而是 Agent 通过 `collect` 工具按源 code 调 |
| Lens（视角） | **声明式 Skill**（MD 文件） | 复用 Pi SKILL.md 机制 |
| Vault（沉淀库） | `vault` 表（新） + `vault_entry`（新） | 跨 session 的洞察沉淀 |
| `run-watch`（编排） | Pi Agent Runtime + 平台受控工具集 | 见 §5.3 |
| Claude Code 运行时 | **Pi Agent SDK** | 见 §5.2 |

> **关键差异**：Signex 把每个数据源做成一个 skill，让 Claude 自己选；我们**反其道**——数据源是配置化的 `ICollector`，Agent 只看到一个 `collect({ sourceCode })` 工具。这样源从 16 个扩到 100 个也无需改 Agent，且源逻辑可被 Mode 1 复用。

### 5.2 Pi Agent SDK 集成

依赖：`@mariozechner/pi-coding-agent`（运行时）+ `pi-gateway`（可选，多会话调度）。我们不暴露其 CLI，而是**程序化驱动**：

```ts
// apps/server/src/insight/runtime.ts （示意）
import { createAgent, type ExtensionAPI } from '@mariozechner/pi-coding-agent';

export async function runInsightSession(input: {
  userId: number;
  intent: string;
  skillSet: string[];      // 允许加载的 skill name 白名单
  budget: SessionBudget;   // token/步数/工具调用次数硬上限
}): Promise<InsightSessionResult> {
  const ext = createInsightExtension(input);   // 注册平台受控工具
  const agent = createAgent({
    model: fastify.llm.chat,
    extensions: [ext],
    skills: loadSkills(input.skillSet),        // 从 DB 加载声明式 skill
    systemPrompt: buildSystemPrompt(input),
    budget: input.budget,
  });
  return await agent.run(input.intent);
}
```

集成边界：
- **`createAgent` / `ExtensionAPI` 来自 Pi**，我们只实现一个 `insightExtension(pi)` 注册平台工具（参考 Pi 官方 `rolePersonaExtension` 写法）。
- **不**让 Pi 用它自带的 `bash` / `edit` / `read` 等代码工具 —— 我们的扩展**只**注册数据相关工具，从根上杜绝「Agent 改文件」。
- Skill 走 Pi 原生 SKILL.md 三级渐进式加载（metadata 常驻 / body 触发时加载 / 资源按需）。

### 5.3 平台受控工具集（白名单，全部走平台通道）

Agent 能用的工具**只有**这些，全部由我们的扩展注册，**全部经 `fastify.http` 出网、全部写 `agent_tool_call` 表**：

| 工具 | 作用 | 内部实现 | 安全约束 |
|---|---|---|---|
| `collect({ sourceCode, query? })` | 调统一采集器 | `fastify.collectors.get(type).fetch(...)` | sourceCode 必须在 `sources` 表且 enabled；query 仅对 query 模式源生效 |
| `search({ query, sourceCode? })` | 语义/关键词搜索 | 默认走 `search-tavily` 等 query 模式源 | 同上；结果走指纹去重 |
| `extract({ url })` | 正文补全 | `WebScraperCollector` (readability/firecrawl) | 单 URL；maxBytes 上限 |
| `queryArticles({ keywords?, category?, since? })` | 查已有 Article 池 | drizzle select | 只读 |
| `vaultRead({ query })` | 读沉淀库 | 全文 like / 标签 | 只读 |
| `vaultWrite({ title, body, tags })` | 写沉淀库 | insert vault_entry | **需 Skill 显式授权**（frontmatter `vault_write: true`） |
| `finalize({ reportMarkdown })` | 产出报告 | 写 insight_session + 可选 reports | 必须调，否则 session 无产出 |

**没有** `bash` / `fetch` / `exec` / 文件读写工具。这是「更安全」的核心。

### 5.4 声明式 Skill（MD + frontmatter）

复用 Pi 的 SKILL.md 格式，存 DB（`skill_revision` 表带版本与 audit），热加载。结构：

```markdown
---
name: lens-deep-insight
description: 综合分析 — 关键发现、趋势、行动建议。当用户要深度报告时触发。
version: "1.0.0"
tools: [collect, search, queryArticles, extract, vaultRead, vaultWrite, finalize]
vault_write: true
budget:
  maxSteps: 25
  maxToolCalls: 40
  maxTokens: 60000
trigger:
  keywords: [深度, 详尽, 综合, 全面分析]
---

# 深度洞察 Lens

## 工作流
1. 解析意图，决定要查哪些 sourceCode（参考 references/source-catalog.md）
2. 并行 collect 3–5 个源，去重后看条数是否够
3. 不够则 search 补 query
4. queryArticles 看池里是否已有处理过的相关 Article
5. extract 对最关键的 3 条抓正文
6. 综合产出：关键发现 / 趋势 / 行动建议
7. vaultWrite 沉淀跨会话洞察
8. finalize 输出 Markdown 报告

## 输出格式
...
```

- frontmatter 字段：`name / description / version / tools(白名单) / budget / trigger.keywords / vault_write`。
- body：自然语言 prompt + 工作流（Pi 三级加载，body 触发时进上下文）。
- `references/` `scripts/` `assets/` 可挂（Pi 原生支持），但 scripts 在我们这里**不执行**（只作为参考文本注入），因为我们的工具是平台注册的，不是 Pi 的 bash。
- 默认 skill 集（从 Signex 改写）：`lens-deep-insight` / `lens-flash-brief` / `lens-dual-take` / `lens-timeline-trace` + 一个 `watch-shape`（把当次 session 转成长期订阅的辅助 skill）。

### 5.5 安全边界（比 Signex 更严）

| 维度 | Signex | 我们 |
|---|---|---|
| 运行时 | Claude Code（全权） | Pi Agent + **白名单工具**（无文件/exec） |
| 出网 | httpx 直连 | **强制经 `fastify.http`**（统一代理 + 审计） |
| Skill 加载 | 文件系统，无版本 | DB `skill_revision` + audit log + 启用开关 |
| 预算 | 无 | frontmatter `budget` + 运行时硬截断（超限 abort） |
| 数据写 | Agent 直写文件 / SQLite | 只能通过 `vaultWrite` / `finalize` 受控工具 |
| 多用户 | 单用户 | 每 session 绑 userId，工具调用全记 `agent_tool_call` |
| 可观测 | 无 | `insight_session` + `agent_step` + `agent_tool_call` 三表全 trace |
| 沙箱 | 无 | Phase 5 起 Agent 进程独立容器（与主服务隔离） |

### 5.6 与 Mode 1 的互通

- **Mode 2 → Mode 1**：用户在 Mode 2 拿到一个好的洞察，可一键「保存为订阅」（`watch-shape` skill 生成 categoryCodes + keywords 写 `subscriptions`），之后由 Mode 1 周期跑。
- **Mode 1 → Mode 2**：Mode 1 的 `articles` 池对 Mode 2 的 `queryArticles` 工具只读可见，Agent 不必每次都重新采集。
- **共享 vault**：Mode 1 的处理管道在生成 `trendComment` 时，可读 vault 做参考；Mode 2 写 vault。

## 6. 数据模型增量（ADD，不破坏 Phase 0 的 12 表）

新增 5 张表（命名加 insight_/vault 前缀，避免与既有冲突）。详细 DDL 在实施阶段落到 `db/schema.ts` 并生成迁移。此处给字段语义：

```
insight_session
  id, user_id→users, intent(text), skill_set(json), 
  status(enum: RUNNING/SUCCESS/FAILED/ABORTED), 
  budget(json), used_tokens, used_steps, used_tool_calls,
  report_markdown(longtext), source_article_ids(json),
  started_at, finished_at, error(text)

agent_step                       -- Agent 每一步思考（用于回放）
  id, session_id→insight_session, 
  step_no, role(enum:ASSISTANT/TOOL/SYSTEM),
  content(text), tool_calls(json), tokens, created_at

agent_tool_call                  -- 每次工具调用（审计）
  id, session_id→insight_session, step_id→agent_step,
  tool(enum:COLLECT/SEARCH/EXTRACT/QUERY_ARTICLES/VAULT_READ/VAULT_WRITE/FINALIZE),
  args(json), result(json), ok(bool), error(text), 
  duration_ms, created_at

skill_revision                   -- 声明式 skill 版本
  id, name(unique with version), version, 
  frontmatter(json), body_md(longtext),
  author_id→users, enabled(bool), created_at, 
  audit_note(text)               -- 改动说明，强制写

vault_entry                      -- 跨 session 洞察沉淀
  id, title, body_md(longtext), tags(json),
  source_session_id→insight_session, 
  pinned(bool), created_at, updated_at
```

> 与既有 `feedback` / `reports` / `report_items` 关系：Mode 2 产出的报告若实体化，复用 `reports` 表（issueNo 用 `INS-{sessionId}` 前缀），其 `report_items` 仍挂 `articles`；纯 Markdown 洞察不进 `reports`，只留 `insight_session.report_markdown`。

## 8. API 增量（关键端点）

### Mode 1（Phase 1 既定，仅列出与基座相关）
- `POST /admin/sources` / `GET/PUT/DELETE` —— SourceConfig 按 type 校验（zod）。
- `POST /admin/sources/:code/test` —— 手动跑一次采集器，回显前 N 条（不落库）。
- `POST /admin/collect/run` —— 触发全局或单源采集（入队 collection.worker）。

### Mode 2（新）
- `POST /insight/sessions` —— `{ intent, skillSet?, budget? }` 创建 session，返回 sessionId + SSE 流。
- `GET /insight/sessions/:id/stream` —— SSE：实时推 agent_step / tool_call。
- `GET /insight/sessions/:id` —— 取最终报告 + trace。
- `POST /insight/sessions/:id/to-subscription` —— 一键转 Mode 1 订阅。
- `GET /admin/insight/sessions` —— 管理端：列表 / 筛选 / 预算用量。
- `GET /admin/insight/sessions/:id/trace` —— 全 trace 回放（步骤 + 工具调用 + 耗时 + token）。
- `POST /admin/skills` / `PUT` —— 上传新版本（写 skill_revision，带 audit_note）。
- `POST /admin/skills/:name/enable` / `disable` —— 启停。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| Pi Agent SDK 内网装不上 / 版本漂移 | 把 Agent 运行时抽成 `IAgentRuntime` SPI（registerTool/run/runWithStream），Pi 是默认实现，必要时可换 Vercel AI SDK 自写循环兜底（W1 留白） |
| Agent token 失控 | budget 硬截断 + 单 session 上限 + 管理端监控 + 超限告警 |
| Skill 投毒（恶意 prompt） | skill_revision 带 audit + ADMIN 才能启用 + 工具白名单兜底（即使 prompt 作恶也调不到 bash） |
| 采集器在内网打不开目标站 | 代理配置 + 源健康统计（学习 Signex source_health）+ collect_logs rollup |
| Mode 2 与 Mode 1 争抢 LLM 配额 | 队列优先级：Mode 1 cron 低优，Mode 2 用户发起高优 |
| newsnow 选择器随目标站改版失效 | 源种子只作起点，管理端可改 config，不写死代码；选择器失效由 collect_logs 反映 |
