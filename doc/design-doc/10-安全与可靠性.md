# 10 · 安全与可靠性

## 10.1 认证与授权

- **认证**：Bearer token（外部登录服务签发）→ Fastify `auth.ts` preHandler 用 `jose` 解 JWT 取 `id`/`name` → 查库定 `role`。
- **授权**：
  - 用户端路由：登录即可（USER/ADMIN）。
  - 管理端路由：`role === 'ADMIN'`，否则 403。
- **平台不存储密码**：登录由外部服务，平台只验 token。

## 10.2 限流与校验

- **限流**：`@fastify/rate-limit`，防采集触发与 API 滥用。
- **参数校验**：Fastify route schema + zod，拒绝非法入参。
- **SQL 注入**：Drizzle 全参数化查询，无字符串拼接。
- **XSS**：前端默认 Vue 转义；富文本（如 AI 生成的 summary）渲染前净化。

## 10.3 任务可靠性（BullMQ）

- 每个队列（collection/processing/report/delivery）：
  - **指数退避重试**：失败自动重试，避免瞬时故障。
  - **死信队列**：超过重试次数进入死信，不丢失。
  - **幂等**：同一 Report 重复推送不产生重复 notification（幂等键）。
  - **可观测**：Bull Board 或自建面板查看队列状态。

## 10.4 密钥管理

- 敏感配置（JWT 秘钥、代理、各源 api key、通道密钥）：
  - 运行时来自环境变量 / 配置中心，**不入源码**。
  - `sources.config` 与通道配置中的 key **加密存储**于 DB（密钥来自环境变量）。
- `.env` 文件不入版本控制（`.gitignore`），提供 `.env.example` 模板。

## 10.5 内网边界

- 出网仅限 RSS/搜索，经管理端配置代理。
- LLM、DB、Redis、推送通道全部内网。
- 不暴露公网端口（除非通过内网网关）。

## 10.6 日志与可观测

- 三类日志可在管理端 dashboard 汇总：
  - `collect_logs`（采集）
  - processing 任务状态 + token 用量（处理）
  - `notification_logs`（推送）
- 错误集中可见，支持手动重试 / 重推。

## 10.7 数据保留

- `raw_items` / `collect_logs` 可配置保留期，定期清理（避免无限增长）。
- `reports` / `notification_logs` 长期保留（存档 + 审计）。
- `feedback` 长期保留（回流优化）。
