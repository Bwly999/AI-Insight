## 14.2 留白项（使用方填白）

### 14.2.1 认证留白
- **JWT 秘钥来源**：环境变量 / 配置中心（建议环境变量 `JWT_SECRET`）。
- **jose 解包 claims 解析**：从 JWT payload 提取 `id`/`name` 的具体字段路径与解包逻辑。
- **`externalId` ↔ users 映射策略**：
  - 建议：首次见到 externalId 时自动建 `users` 记录，role 默认 USER。
  - 备选：管理员预置用户名单，未在名单内的 token 拒绝。
  - 待使用方确认。

### 14.2.2 登录代码
- 前端路由加载时调用使用方登录接口取得 token 的逻辑，**由使用方实现**，平台留 axios 拦截器占位。

### 14.2.3 内网推送通道
- Email / 企业微信 / 飞书 / 钉钉 / Telegram 等，**由使用方按 `INotificationChannel` 接口实现**并注册。平台仅提供 ConsoleNotifier。

### 14.2.4 内网采集器
- 内部知识库 / 内网数据源，**由使用方按 `ICollector` 接口实现**并注册。

### 14.2.5 LLM baseURL / 模型名
- 内网模型服务的 OpenAI 兼容地址与模型名，由使用方通过 `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` 环境变量配置。

## 14.3 建议的实现选择（待确认，不阻塞 Phase 0）

### 14.3.1 处理触发时机
- **建议**：独立处理 cron（如每小时），与报告 cron 解耦。
- 备选：采集后攒批触发。
- 理由：独立 cron 更简单可控，Article 池持续更新，报告 cron 触发时取最新池。

### 14.3.2 externalId 映射
- **建议**：首次见到自动建 USER 记录（JIT provisioning），降低运维负担。
- 风险：任何能拿到合法 token 的人都会自动入库。
- 备选：白名单预置，更安全但需运维。

### 14.3.3 时间窗默认值
- ReportSchedule 的 `periodHours`：
  - 日报建议 24，周报建议 168（7 天）。
  - 管理端可配。

### 14.3.4 报告 issueNo 规则
- **建议**：`{scheduleCode}.{YYYYMMDD}-{seq}`，如 `DAILY.20260617-001`。
- 唯一约束 `(scheduleId, issueNo)`。

## 14.4 演进项（v2+，当前不做）

- **反馈数据回流推荐**：用 `feedback`（USEFUL/USELESS）调整裁剪权重，个性化排序。
- **全文检索**：当前只按期浏览，v2 可加 PostgreSQL tsvector 或 Elasticsearch（但当前用 MySQL，需评估方案）。
- **多租户**：当前无多租户，若未来需要按部门隔离，需加 `orgId` 贯穿各表。
- **SSR / SEO**：内网场景无需求，保持纯 SPA。
- **embeddings / 向量去重**：若内网 LLM 未来提供 embedding，可引入 pgvector 或 MySQL 向量方案优化语义去重。
