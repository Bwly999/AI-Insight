# 09 · 基础设施与部署

## 9.1 docker-compose 编排

单机起步，全内网。`docker-compose.yml` 拉起以下服务：

| 服务 | 镜像 | 端口 | 说明 |
|---|---|---|---|
| `mysql` | mysql:8 | 3306 | 业务数据库 |
| `redis` | redis:7 | 6379 | BullMQ 队列 + 缓存 |
| `server` | 自构建 | 3000 | Fastify 后端（API + worker 可同进程或拆分） |
| `user` | nginx | 8080 | 用户端静态 + 反代 |
| `admin` | nginx | 8081 | 管理端静态 + 反代 |

```yaml
# docker-compose.yml（示意）
services:
  mysql:
    image: mysql:8
    environment:
      MYSQL_DATABASE: ai_insight
      MYSQL_ROOT_PASSWORD: ${MYSQL_PASSWORD}
    volumes: [ "mysql-data:/var/lib/mysql" ]
  redis:
    image: redis:7
    volumes: [ "redis-data:/data" ]
  server:
    build: ./apps/server
    environment:
      DATABASE_URL: mysql://root:${MYSQL_PASSWORD}@mysql:3306/ai_insight
      REDIS_URL: redis://redis:6379
      LLM_BASE_URL: ${LLM_BASE_URL}      # 内网 LLM
      LLM_API_KEY:  ${LLM_API_KEY}
      JWT_SECRET:   ${JWT_SECRET}        # 留白：使用方填
    depends_on: [ mysql, redis ]
  user:
    build: ./apps/user
    ports: [ "8080:80" ]
    depends_on: [ server ]
  admin:
    build: ./apps/admin
    ports: [ "8081:80" ]
    depends_on: [ server ]
volumes:
  mysql-data:
  redis-data:
```

## 9.2 出网（HTTP 代理）

- **仅 RSS / 搜索出网**，且经管理端配置的自定义代理。
- **不走环境变量**，由管理端 `/admin/proxy` 配置（存库或配置中心），应用内自定义 HTTP 客户端读取。
- `http-client.ts` 插件用类库（undici/got）实现代理客户端，全局生效于所有出网请求（采集器、搜索）。
- 未配置代理时不出网（采集仅靠内网可达源）。

## 9.3 LLM 接入

- `llm.ts` 插件用 Vercel AI SDK，`baseURL` 指内网模型服务（OpenAI 兼容地址）。
- 仅 chat（无 embedding）。
- 配置来自环境变量：`LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`。

## 9.4 配置管理

- `.env` 区分 `development` / `production`。
- 敏感项（JWT 秘钥、代理、各源 api key、通道密钥）**注入不入库明文**。
- `sources.config` 与 `notification_channels` 中的 key **加密存储**（如 AES，密钥来自环境变量）。

| 配置项 | 来源 | 示例 |
|---|---|---|
| DATABASE_URL | env | mysql://root:pwd@mysql:3306/ai_insight |
| REDIS_URL | env | redis://redis:6379 |
| LLM_BASE_URL | env | http://internal-llm/v1 |
| LLM_API_KEY | env | internal |
| LLM_MODEL | env | internal-model-name |
| JWT_SECRET | env | **留白使用方填** |
| HTTP 代理 | 管理端配置 | host/port/auth |
| 各源 api key | sources.config（加密） | — |
| 通道密钥 | channels（加密） | — |

## 9.5 CI

脚本化，本地或 CI 平台执行：

```bash
pnpm install
pnpm lint
pnpm typecheck
pnpm build
pnpm db:gen          # 生成迁移（如有 schema 变更）
docker compose build
```

- lint + typecheck + build 全绿才允许镜像构建。
- 迁移文件纳入版本控制。

## 9.6 数据库迁移

- schema：`apps/server/src/db/schema.ts`（Drizzle）。
- 迁移目录：`apps/server/drizzle/`。
- 命令：`pnpm db:gen`（生成）→ `pnpm db:push`（应用）。
- 部署时容器启动前执行迁移（entrypoint 脚本）。

## 9.7 演进路径

- 起步：docker-compose 单机。
- 演进：镜像化后可平滑迁 K8s；server 可拆为 API 进程 + worker 进程独立扩缩容；MySQL/Redis 可外置托管实例。
