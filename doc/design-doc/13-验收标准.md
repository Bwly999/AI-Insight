# 13 · 验收标准

每条均为**可客观验证**的检查项。Phase 0 必达，其余为对应 Phase 验收。

---

## A. Phase 0 — 架构骨架验收

- [ ] **A1 仓库结构**：根目录存在 `apps/{user,admin,server}`、`packages/{shared-types,shared-ui,shared-config}`、`pnpm-workspace.yaml`、`turbo.json`。
- [ ] **A2 依赖安装**：`pnpm install` 在干净环境一次性成功，无 peer 警告阻断。
- [ ] **A3 构建编排**：`pnpm build`（turbo）按依赖拓扑顺序构建全部包，无失败；`pnpm lint` 与 `pnpm typecheck` 全绿。
- [ ] **A4 后端启动**：`apps/server` 能独立启动，`GET /health` 返回 200；Fastify 装载 `db/queue/http-client/llm/collectors/notifiers/scheduler` 全部插件无错误。
- [ ] **A5 数据库**：Drizzle schema 覆盖 [06-数据模型](./06-数据模型.md) 全部表；`drizzle-kit push/migrate` 在空 MySQL 成功建表；`db.ts` 插件 `decorate('db')` 可用。
- [ ] **A6 前端启动**：`apps/user` 与 `apps/admin` 各自 `pnpm dev` 可启动，访问首页 200，Tailwind 生效。
- [ ] **A7 编排**：`docker-compose up` 一键拉起 `mysql + redis + server + user + admin`，全部 healthy；两端 Nginx 反代到 server 通畅（`/api/health` 200）。
- [ ] **A8 类型共享**：`shared-types` 中 SPI 接口（`ICollector`/`INotificationChannel`）与 DTO 可被 `apps/server` 与前端同时导入，无类型冲突。
- [ ] **A9 认证骨架**：`auth.ts` preHandler 实现到位（jose 解包留白点用 TODO 占位），`GET /auth/me` 在带合法（手工构造）token 时返回 `{id,name,role}`；无 token 返回 401。
- [ ] **A10 守卫骨架**：任一 `/admin/*` 路由对 `role=USER` 返回 403，对 `role=ADMIN` 返回 200（可用假数据验证）。

## B. Phase 1 — 采集闭环验收

- [ ] **B1 SPI 注册**：`fastify.registerCollector('RSS', …)` 后，调度按 type 正确命中实现。
- [ ] **B2 RSS 采集**：管理端新建一个 `RSS` 源（填真实 feed url）→ 手动触发 → `raw_items` 出现新记录，`collect_logs` 记 success。
- [ ] **B3 搜索采集（API 型）**：新建 `SEARCH_API` 源（填 endpoint+key）→ 触发 → 成功抓取结果并入库。
- [ ] **B4 搜索采集（爬虫型）**：新建 `SEARCH_CRAWL` 源（填 `bing?q=` 模板 + 选择器）→ 触发 → 成功入库。
- [ ] **B5 全局 cron**：配置采集 cron（如每 5min 用于测试）→ 到点自动触发所有 enabled 源。
- [ ] **B6 去重**：同一 URL 重复采集不会产生重复 `raw_items`（fingerprint 唯一约束生效）。
- [ ] **B7 代理**：管理端配置 HTTP 代理后，出网请求（RSS/搜索）实际经代理（抓包或代理日志可见）；未配置时不走代理且不崩。
- [ ] **B8 重试与日志**：模拟源失败 → BullMQ 指数退避重试；`collect_logs` 记录 error；死信队列可见。
- [ ] **B9 管理端页面**：数据源/代理/cron 三页 CRUD 可用，手动触发与日志查看正常。
- [ ] **B10 Playwright 预留**：`WEB_SCRAPER` type 已注册、依赖已装、接口可调（深度抓取可返回占位），不阻塞主流程。

## C. Phase 2 — AI 处理验收

- [ ] **C1 LLM 连通**：`llm.ts` baseURL 指内网，一次 `generateText` 与一次 `generateObject` 调用成功返回。
- [ ] **C2 五阶段产出**：处理一批 raw_items 后，`articles` 表字段齐全：`categoryCode / summary(中文) / heat / critical / trendComment / tags`。
- [ ] **C3 中文输出**：summary 与 trendComment 均为中文（外文源也被概括为中文）。
- [ ] **C4 语义去重**：构造两条内容相似但 URL/标题不同的条目 → 处理后仅保留一条。
- [ ] **C5 处理监控**：管理端可见各阶段任务状态、token 用量、重跑入口；失败可重跑。
- [ ] **C6 事后纠错**：管理端可修改某 article 的 summary/heat/critical 并持久化。

---

## D. Phase 3 — 报告与用户端验收

- [ ] **D1 调度触发**：新建一个 ReportSchedule（cron 设近点）→ 到点为该 schedule 下所有 active subscription 生成 `reports` 记录（status=READY）。
- [ ] **D2 裁剪正确**：某用户订阅领域=A+关键词 K → 其 report 的 bodyJson 仅含命中 A 或 K 的 articles。
- [ ] **D3 头条**：每份 report 有 `headlineJson`，且为该用户命中的最高 heat 条目（critical 优先）。
- [ ] **D4 深度内容**：bodyJson 含领域点评/趋势/编辑荐语片段。
- [ ] **D5 用户端视觉**：用户端首页布局复刻 `v2-editorial.html`（头版/统计卡/本周精选/供稿榜/档案），数据来自后端 report。
- [ ] **D6 订阅设置**：用户可勾领域、填关键词、选 schedule、设通道偏好并保存生效。
- [ ] **D7 往期浏览**：`/archive` 按期列出历史 reports，`/reports/:id` 可看详情。
- [ ] **D8 反馈/收藏**：用户对 article 标记 USEFUL/USELESS/COLLECT，`feedback` 表落库，`/feedback` 可查。

---

## E. Phase 4 — 推送闭环验收

- [ ] **E1 SPI 注册**：`fastify.registerNotifier('CONSOLE', …)` 后 delivery 按 channel 命中。
- [ ] **E2 Console 推送**：report 生成后 delivery 调用 ConsoleNotifier，`notification_logs` 记 success，控制台打印 payload。
- [ ] **E3 通道偏好**：subscription.channels 决定调用哪些通道；未配置的通道不调用。
- [ ] **E4 内网扩展性验证**：实现一个自定义 `TestChannel` 注册后，不改核心代码即可被调用并记录。
- [ ] **E5 失败与重推**：模拟通道失败 → `notification_logs` 记 error；管理端「手动重推」可重新触发该 report 推送并成功。
- [ ] **E6 幂等**：同一 report 重复推送不产生重复 notification（幂等键）。
- [ ] **E7 通道管理页**：管理端可见已注册通道、配置密钥、连通性测试返回结果。

---

## F. 横切验收（贯穿各 Phase）

- [ ] **F1 类型一致**：前后端通过 `shared-types` 共享 DTO，无手写重复类型导致漂移。
- [ ] **F2 权限**：所有 `/admin/*` 对 USER 返回 403；用户端接口对匿名返回 401。
- [ ] **F3 配置隔离**：敏感配置（JWT 秘钥/代理/各 key/通道密钥）均来自环境变量或加密存储，源码与 schema 中无明文。
- [ ] **F4 可观测**：每个 BullMQ 队列有命名、有日志；采集/处理/推送三类日志可在管理端 dashboard 汇总。
- [ ] **F5 幂等**：同一 report 重复推送不产生重复 notification（幂等键）。
- [ ] **F6 文档**：README 含本地启动、docker-compose、Drizzle 迁移、内网扩展点（采集器/通道/LLM/认证）的接入示例。
- [ ] **F7 单元/集成测试**：核心 SPI（collectors/notifiers）与 worker 有基本测试覆盖；CI 中运行。
