# 12 · 分阶段路线图

## 阶段总览

| Phase | 目标 | 关键交付 |
|---|---|---|
| **0** | 架构骨架 | 全链路可启动，无业务逻辑 |
| **1** | 采集闭环 | RSS/搜索入库 + 日志可见 |
| **2** | AI 处理 | Article 池产出 |
| **3** | 报告 + 用户端 | 用户端可看报告 |
| **4** | 推送闭环 | Console 推送可见 |
| **5** | 加固 | 生产可用 |

---

## Phase 0 · 架构骨架（使用方指定起点）

**范围**：Monorepo + Fastify + Vue3 + MySQL(Drizzle) 骨架，验证架构与启动，**不实现业务逻辑**。

### 交付
- pnpm workspaces + turborepo 工程骨架。
- `apps/server`：Fastify 启动 + 全部插件装载（auth/db/queue/http-client/llm/collectors/notifiers/scheduler）+ `GET /health`。
- `apps/user` / `apps/admin`：Vite + Vue3 + Tailwind 空工程，首页可访问。
- `packages/shared-types`：SPI 接口 + DTO 定义。
- `packages/shared-ui`：编辑风设计 token。
- `packages/shared-config`：tsconfig / eslint / tailwind / drizzle 预设。
- Drizzle schema（第六部分全表）+ `drizzle-kit` 迁移就绪。
- `docker-compose.yml`：mysql + redis + server + user + admin 一键拉起。
- `auth.ts` preHandler 骨架（jose 解包留白 TODO）+ `GET /auth/me` + admin 守卫骨架。

### 验收
见 [13-验收标准 A 组](./13-验收标准.md#a-phase-0--架构骨架验收)。

---

## Phase 1 · 采集闭环

**范围**：采集器 SPI + 三个默认实现（Playwright 预留）+ 全局采集 cron + 去重入库 + 代理 + 管理端采集相关页。

### 交付
- `ICollector` 注册机制 + RssCollector / SearchApiCollector / SearchCrawlCollector / PlaywrightScraperCollector(预留)。
- 全局采集 cron + collection-queue + collection.worker。
- 指纹去重入库 + collect_logs。
- `http-client` 插件（管理端配置代理）。
- 管理端：数据源 / 代理 / cron 三页 CRUD + 手动触发 + 日志查看。

### 验收
见 [13-验收标准 B 组](./13-验收标准.md#b-phase-1--采集闭环验收)。

---

## Phase 2 · AI 处理

**范围**：LLM 接入 + 处理五阶段 + 管理端处理监控 + 事后纠错。

### 交付
- `llm.ts` 插件（Vercel AI SDK 指内网）。
- processing.worker 五阶段（去重/分类/摘要/热度/综合点评）。
- 管理端：处理监控（任务状态/token 用量/重跑）+ Article 事后纠错。

### 验收
见 [13-验收标准 C 组](./13-验收标准.md#c-phase-2--ai-处理验收)。

---

## Phase 3 · 报告 + 用户端

**范围**：报告生成（按 schedule cron 裁剪组装实体化）+ 用户端全页（复刻原型视觉）。

### 交付
- report.worker（按 ReportSchedule cron 触发，为该目标下所有用户裁剪组装）。
- Report 实体化存档 + report_items。
- 用户端：本期/往期/详情/订阅设置/反馈页（视觉复刻 `v2-editorial.html`，设计规范见 [15-UIUX设计](./15-UIUX设计.md)）。
- 管理端：ReportSchedule CRUD + 报告查看。

### 验收
见 [13-验收标准 D 组](./13-验收标准.md#d-phase-3--报告与用户端验收)。

---

## Phase 4 · 推送闭环

**范围**：推送通道 SPI + ConsoleNotifier + delivery + 日志 + 管理端通道管理/手动重推。

### 交付
- `INotificationChannel` 注册机制 + ConsoleNotifier。
- delivery.worker + notification_logs（含幂等）。
- 管理端：通道管理 + 手动重推。

### 验收
见 [13-验收标准 E 组](./13-验收标准.md#e-phase-4--推送闭环验收)。

---

## Phase 5 · 加固

**范围**：生产可用性 + 可观测 + 文档化。

### 交付
- 限流（`@fastify/rate-limit`）完善。
- 错误告警（采集/处理/推送失败通知管理员）。
- 反馈数据回流推荐（v2，基于 feedback 优化裁剪权重）。
- 数据保留策略（raw_items/collect_logs 定期清理）。
- 内网扩展点接入文档与示例。
- 可观测面板（Bull Board 或自建）。

### 里程碑
平台达到内网生产可用，使用方可按文档自行接入 Email/企微/飞书等通道与内网数据源。
