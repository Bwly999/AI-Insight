# Phase 5 · 加固

> 依据：`design-doc/12-分阶段路线图.md` Phase 5、`10-安全与可靠性.md`、`11-内网扩展点.md`
> 前置：Phase 1A–4 验收通过（附录 C.B/C/D/E 全绿）
> 验收：附录 C.F（F1–F7 横切）

## 1. 目标与范围

把平台从「功能可用」升级到「生产可用」。覆盖：限流 / 告警 / 数据保留 / 反馈权重回流 / 可观测面板 / 用户管理 / 内网扩展文档 / Agent 进程隔离（W8）。

**特点**：本 Phase 无单一交付物，是一组横切加固项，可按优先级分批落地。**生产部署前必须完成 F3（配置隔离）+ F6（文档）+ D 留白确认**。

## 2. 依赖项

- 已装：`@fastify/rate-limit` / `@fastify/helmet` / `@fastify/cors`（Phase 0 装齐）
- 新增：`bull-board`（可选，可观测面板）或自建
- 修改：多个插件 + admin 页

### [ ] 任务 5.4 可观测面板（dashboard 真实数据）

> 验收：F4

**文件路径**
- 修改 `apps/server/src/routes/admin.ts` 的 `/admin/dashboard` — 替换 Phase 0 的零值
- 修改 `apps/admin/src/views/DashboardView.vue` — 替换占位

**实现要点**

后端 `DashboardStats` 填充：
- `collectedToday`：`SELECT COUNT(*) FROM raw_items WHERE captured_at >= CURDATE()`
- `pendingProcess`：`SELECT COUNT(*) FROM raw_items WHERE id NOT IN (SELECT raw_item_id FROM articles WHERE raw_item_id IS NOT NULL)`
- `reportsThisIssue`：今日生成的 report 数
- `deliverySuccessRate`：`SELECT status, COUNT(*) FROM notification_logs WHERE created_at >= CURDATE() GROUP BY status` 算比率
- `queueHealth`：查 BullMQ 各队列 `getWaiting/getActive/getFailed` 计数
- `recentErrors`：查 collect_logs/notification_logs 最近 status=FAILED 的 10 条

前端：4 个卡片 + 4 个队列行 + 错误列表，全部接真实数据。

**验收点**
- F4

**文件路径**

**实现要点**
- raw_items：保留 90 天，更早的删除（articles 已固化，删 raw_items 不影响报告）

- notification_logs：保留 90 天
- agent_steps/agent_tool_calls：保留 30 天（trace 太大）
- 清理脚本：`DELETE FROM xxx WHERE created_at < DATE_SUB(NOW(), INTERVAL N DAY) LIMIT 10000`（分批避免锁表）
