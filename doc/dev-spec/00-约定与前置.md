## 3. 代码风格

### 3.1 TypeScript

- **严格模式**：所有 tsconfig 继承 `shared-config/tsconfig/base.json`（`strict: true` + `noUncheckedIndexedAccess: true`）。
- **ESM**：server 是 `type: module`，import 必须带 `.js` 扩展名（即使源是 `.ts`）。
- **无 `any`**：用 `unknown` + 类型守卫，或显式定义接口。`@ts-expect-error` 需配注释。
- **命名**：PascalCase 类型/接口/类，camelCase 函数/变量，UPPER_SNAKE 常量，kebab-case 文件名（Vue 组件除外，PascalCase）。
- **枚举**：DB 用 Drizzle `mysqlEnum`；TS 用联合字符串类型（`type Foo = 'A' | 'B'`），不用 `enum` 关键字。

### 3.2 Fastify 插件

- 用 `fastify-plugin`（`fp`）包装，确保装饰器暴露到根实例。
- 插件名：`{ name: 'xxx' }` 必填。
- 装饰器类型声明：每个插件文件底部必须有 `declare module 'fastify' { interface FastifyInstance { ... } }`。
- `onClose` 钩子：所有持有资源的插件（db pool / redis / undici agent）必须注册 cleanup。

### 3.3 路由

- 路由模块导出 `async function(app: FastifyInstance)` 默认函数。
- 在 `routes/index.ts` 的 `registerRoutes` 中 `app.register(xxx)`。
- 权限：`preHandler: [app.auth]`（需登录）或 `[app.auth, app.requireAdmin]`（需 ADMIN）。
- 入参用 zod schema 校验：`schema: { body: CreateSourceBody }`，Fastify 自动校验 + 序列化。
- 出参：直接 return 对象/数组，Fastify 序列化；错误 throw `FastifyError`。

### 3.4 Drizzle

- 表定义在 `apps/server/src/db/schema.ts`，一个 `mysqlTable` 一张表。
- **PK 一律 `int().autoincrement().primaryKey()`**（不用 serial/bigint，保持 FK 类型一致）。
- **时间戳一律 `default(sql\`CURRENT_TIMESTAMP\`)`**（MySQL 严格模式要求显式默认值）。
- FK 用 `.references(() => otherTable.id)`，不声明 `onDelete`（默认 RESTRICT，由应用层处理）。
- 迁移：`corepack pnpm db:gen`（生成）→ `corepack pnpm db:migrate`（应用，走 `scripts/apply-migration.mjs` 绕过 drizzle-kit push 的 MySQL 8.0.28 bug）。

### 3.5 Vue 前端

- **`<script setup lang="ts">`**，Composition API，不用 Options API。
- 组件用 PascalCase 命名（`HomeView.vue`），composable 用 `use` 前缀（`useAuth`）。
- 状态用 Pinia（`defineStore`），不用响应式全局变量。
- API 调用经 `api/client.ts` 的 axios 实例（自动注入 Bearer token）。
- 设计 token 来自 `@ai-insight/shared-ui`（CSS 变量 `--paper` / `--ink` / `--vermillion` 等），不硬编码颜色。

## 5. 错误处理约定

### 5.1 后端

- **采集器/worker**：失败 **throw Error**，由调用方（worker）catch 并记日志（`collect_logs.error` / `notification_logs.error`）。不返回 `{ ok: false }` 风格。
- **路由处理**：业务错误 throw `app.httpErrors.xxx()`（Fastify 自动序列化为 JSON 错误响应）。
- **鉴权**：`reply.code(401/403).send({...})`，不走 throw。
- **zod 校验**：用 Fastify 的 `schema` 自动校验，不手写 try/catch。
- **外部调用**（HTTP / LLM）：必须 try/catch，catch 后记日志 + 抛业务错误或降级。

### 5.2 错误响应格式

```json
{ "error": "forbidden", "message": "admin role required", "statusCode": 403 }
```

- `error`：机器可读的 snake_case 错误码。
- `message`：人可读的中文或英文说明。
- `statusCode`：HTTP 状态码。

### 5.3 前端

- axios 响应拦截器统一处理：401 → 清 token 跳登录；403 → 记录 `forbidden`；其他 → toast 错误消息。
- 业务组件不直接 try/catch axios，靠拦截器；除非需要局部错误处理（如上传）。

## 6. 日志约定

### 6.1 后端（pino）

- 用 `req.log` / `app.log`（Fastify 自带 pino），不 `console.log`。
- 级别：`debug`（详细诊断）/ `info`（关键生命周期）/ `warn`（可恢复异常）/ `error`（需关注的失败）。
- 结构化：`app.log.info({ sourceId, count }, 'collection done')`，不字符串拼接。
- 敏感信息（token / 密码 / apiKey）**禁止入日志**。

### 6.2 worker 日志

每个 worker 处理一个 job 时：
```ts
logger.info({ jobId: job.id, sourceId }, '[collection] start');
// ... 业务
logger.info({ jobId: job.id, sourceId, itemsNew }, '[collection] done');
// 失败
logger.error({ jobId: job.id, sourceId, err: err.message }, '[collection] failed');
throw err; // 让 BullMQ 重试
```

### 6.3 前端

- 开发用 `console.warn/error`（不 info，避免噪音）。
- 生产构建移除 console（Vite 配置）。

## 8. 安全约定（横切）

- **敏感配置**：JWT 秘钥 / 代理密码 / 各 apiKey / 通道密钥 **一律从环境变量读**，源码/schema 无明文。
- **apiKey 脱敏**：DB 存加密（Phase 1A 实现加密工具），API 返回脱敏（`hasKey: true` 而非明文）。
- **出网**：所有 HTTP 出网经 `fastify.http`（undici Dispatcher），不允许组件自带 fetch/axios 直连。
- **SQL 注入**：用 Drizzle 查询构造器，不拼 SQL 字符串。
- **XSS**：前端用 Vue 模板自动转义；如需 `v-html`，必须先 sanitize。
- **Mode 2 Agent**：工具白名单，无 bash/exec/fetch；出网经 `fastify.http`；预算硬截断（见 1B/1C）。

## 9. 测试约定

- **测试框架**：Phase 1A 起引入 Vitest（目前未装，1A 第一个任务装）。

## 10. Git 约定

- **分支**：`main` 为主线；大 Phase 用 `phase-1A` / `phase-2` 分支。
- **commit**：`<type>(<scope>): <subject>`，如 `feat(collectors): implement RSS collector`。
- **不提交**：`.env` / `dist/` / `node_modules/` / `*.log`（已在 `.gitignore`）。
- **提交前**：`corepack pnpm typecheck` 全绿。
