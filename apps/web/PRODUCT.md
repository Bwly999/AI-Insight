# Product

## Register

product

## Users

**主要用户：分析师与研究员（analysts / researchers）**——以多来源研究为业的人。

使用场景：他们正在回答一个需要证据支撑的问题——从搜索结果、RSS 订阅、爬取的网页里收集信号，再把它们综合成一条**可辩护、可追溯**的结论。他们是专业人士，不是首次使用者；他们读得懂密集信息，并且**最在意证据深度与来源可追溯性**。

核心任务（job-to-be-done）：把分散在多个数据源里的原始材料，变成一份**每个结论都能一键回溯到来源**的洞察报告。他们要的不是"一个答案"，而是"一个我能验证、能交付的答案"。

## Product Purpose

AI-Insight 是一个 **AI 研究工作台**：它在一个 insight agent 上跑通用户选定的数据源（search / RSS / crawl），**透明地流式展示推理过程**，把每一条结论**锚定在可追溯的引用**上，最终产出一份**编辑级的报告**（Fraunces 衬线承载的交付物）。

它存在的意义：让一个研究员从"我需要搞清楚 X"走到"这是一份有据可查、带来源的回答"，**而不必手动管理几十个标签页**——同时不牺牲任何一步的可验证性。设计服务于产品；设计的成功标准是"用户信任并敢交付这里的产出"。

## Brand Personality

**自信 · 精准 · 可追溯（Confident · Precise · Traceable）。**

不是一个花哨或装饰性的工具——但也**绝不怯懦**。这是一个**有咬合力的数据工具**：在密度有助于理解的地方密集，层级清晰，对比度主动争取注意力而非稀释它。语调直接、专业；产品信任用户的专业能力。

> **战略方向（用户在 init 中明确）：在当前克制的基线上，往"更锐利、更有主张"推。** 同一套翠绿 + 中性 + Inter/JetBrains Mono + 无发光的体系，但要更紧的节奏、更强的层级、更高的对比——让工具看起来"有定见"，而不是"安全"。注意：这里的"锐利"指的是**层级与密度**，不是发光 / 渐变 / 装饰——硬性反 slop 规则（见下）一条都不松绑。

## Anti-references

**绝不该像的东西：**

- **2026 AI 默认审美本身**——奶油 / 沙 / 米色的暖中性背景；玻璃拟态（glassmorphism）；发光（glow）；渐变文字（gradient text）；千篇一律的"图标 + 标题 + 一句话"卡片网格；每个 section 上方加一条全大写宽字距的 eyebrow。仓库已经在主动对抗这些（见提交 "去除 AI 默认视觉特征"、`style.css` 中的 `unslop-ignore` 标记）。
- **装饰性 SaaS 仪表盘**——hero-metric 模板（大数字 + 小标签 + 配套 stats + 渐变点缀），以及"1px 边框 + 16px+ 软宽投影"的 ghost card 套路。
- **被推到怯懦程度的"克制"**——洗白的灰底正文（"为了优雅"的浅灰）、只有发丝线的层级、所有元素视觉权重相同。**克制不等于不可读。** 正文对比必须达标，层级必须可辨。
- **不展示来源与推理的 AI 聊天壳**——只甩答案、不给你验证途径的产品，是本产品的反面。

## Design Principles

由对话与代码推导出的战略原则（非视觉规则）：

1. **Show the work. 展示过程。** 每一条结论都可追溯到来源。引用、推理步骤、证据不是装饰——它们就是产品本身。设计要让"验证"永远只需一次点击。报告里的 `[n]` → 引用链接、EvidencePanel、流式 reasoning 块，都是这条原则的体现，不是"nice to have"。
2. **Confident, not loud. 自信，而非喧哗。** 层级由密度与对比承载，**不靠发光、渐变或装饰**。强字重与清晰权重胜过软投影。克制体现在"没有噪声"，**而不是"没有存在感"**——这一点是当前体系要主动推进的方向（见 Brand Personality 的战略方向）。
3. **Bite over air. 咬合力优先于留白。** 倾向更紧的节奏与更强的层级，而非空旷、怯懦的间距。工具该看起来有定见。但密度必须服务于理解，**绝不能挤垮阅读**——这是"更锐利"与"挤"之间的硬边界。
4. **Instrument-grade legibility. 仪器级可读性。** 正文达到真实对比（≥4.5:1）；数据用 mono 且精确（JetBrains Mono）；状态色对色盲安全、且**绝不只靠颜色**传达。专业人士整天在读——**永远不为"优雅"牺牲可读性**。这条优先级高于一切视觉偏好。
5. **One deliberate editorial voice. 一个刻意的编辑性声音。** 衬线（Fraunces）**只保留给报告这个交付物**——工作变成 deliverable 的那一刻。其余所有界面用 Inter + JetBrains Mono。不要模糊这两个 register：工具态（sans/mono）与交付态（serif）是刻意分层的。

## Accessibility & Inclusion

**目标：WCAG AA。**

- 正文对比 ≥ 4.5:1，大字（≥18px 或 bold ≥14px）≥ 3:1。占位符文字同样要 4.5:1，不接受"灰一点更优雅"。
- **reduced-motion 已完整尊重**（见 `style.css` 末尾），保持现状——任何新动效都必须带 `prefers-reduced-motion` 降级。
- 状态指示**绝不只依赖颜色**——配图标或文字标签（翠绿 / 琥珀 / 玫瑰已是语义色，但仍需形素冗余）。
- 点击目标维持舒适下限；双主题（浅 / 深）均需通过对比检查。
- 数据源类型色（search / rss / crawl）在色盲下仍可区分（已用色相 + 形素区分，设计时保持）。
