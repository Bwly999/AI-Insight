AConsole

仪器控制台 — 把"运行状态"升格为中央遥测模块

核心签名是中央那个 4 格的 mono 遥测条：Status · Elapsed · Sources · Tokens。它直接把"工作台 = 一台仪器"这个产品隐喻可视化——研究员最在意的"它跑到哪了 / 抓了多少源 / 花了多少 token"一眼可见，而不是埋在某个小 pill 里。三栏用 1px 竖线分区，底部加一条 mono 刻度（tonal，不是发光）强化"仪器面板"语义。

BMasthead

报头结构 — 借 editorial 的"分量感"，但严守 register 边界

注意：这不是把朱砂/衬线搬进工作台（DESIGN.md 明令禁止 register 混用）。借的是结构——粗体报名 + 竖线分区 + mono 版次戳 + 双线下沿 rule。强字阶（19px/800）让品牌有"出版物"的分量；版次行（Live · 日期）把每次会话框定成"一期"，呼应产品"产出可交付物"的本质。适合追求"权威感 / 编辑性"的姿态。

CCompact Rail

专业密度条 — Linear / Raycast 风格，把空间还给内容

48px 高（最矮），工具按钮无框纯图标，面包屑把"我在哪"显式标出来（这对多会话研究场景极有用），kbd 提示可见（⌘J / Esc）让专业用户知道有快捷键。状态用极简的跳动点 + mono 时间。这个方向的"主张"是克制即自信——不抢戏，但每个像素都有理由。适合内容为主、chrome 应当退让的场景。

ALedger · 研究账册

会话 = 账册条目。§章节号 + mono 编号 + 来源 glyph + 开口指示

把每个会话当成"账册"里的一条记录：左侧 mono 编号（01、02…）、来源类型用色块 glyph（search/rss/crawl 各一色，色盲安全）、相对时间右对齐。时间桶升格为章节（§I Today / §II This Week），配双线分隔——这是结构分隔，不是卡片装饰。开口指示 ▸/▾ 是仪器感的小细节：选中时展开。最有"研究员在翻账本"的氛围。

BIndex Card · 索引卡

每条会话 = 一张索引卡。边框 + 内部分区 + 来源筛选 chip

每条会话有清晰的边框 + 内部分区（标题区 / 虚线 / 元信息底栏），元信息底栏露出来源类型 + 引用数 + 时间——把"可追溯"这个产品核心价值直接显式化在列表里。顶部新增来源筛选 chip（全部/Search/RSS/Crawl），让研究员按数据源切换视图。悬浮时 tonal 抬升 1px（shadow-sm，不发光）。最有"翻一摞资料卡"的实体感。

CCompact Rail · 编辑器轨

VS Code / Linear 最大密度。表格式行，把视觉噪声压到最低

列表是表格式：表头行（# / Title / Time）+ 每行三列（来源 glyph / 标题 / mono 时间右对齐）。CTA 缩小成内联按钮（不占整行），搜索拆成单独图标按钮。选中态 = 整行 accent-soft tint + 2px 左线（合法的状态指示）。280px 最窄，一屏能看最多会话。这个方向的主张是：给重度用户（几十上百个会话）最高效的扫读。如果用户的痛点是"会话太多找不到"，选这个。

最高扫读效率 表格式结构 280px 最窄 表头 meta 行 CTA 内联化 适合重度用户

§ 取舍 · 怎么选

每个方向都是刻意的，没有"绝对最优"
▲Topbar 推荐

A · Console（仪器感最强，最贴"研究员工作台"隐喻，状态信息升格直接提升产品信任）
C · Compact（如果内容为主、想让 chrome 退让）

B · Masthead 更适合"权威感 / 编辑性"品牌叙事，但若担心双线 rule 太"重"，可作备选。

◀Sidebar 推荐

B · Index Card（引用数外显最贴"可追溯"产品价值，分层最清晰）
A · Ledger（如果想要更强的"研究账册"叙事氛围）

C · Compact 适合会话量极大（50+）的重度用户；当前规模下信息密度可能偏紧。
