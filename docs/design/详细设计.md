# AI-Insight 详细设计方案

> 「AI For 洞察」全栈系统 · 部署于公司内网 · 行业咨询。用户通过对话发起洞察，Agent 据意图调用数据源采集并综合，产出可分享的报告；支持把一次洞察固化为定时任务。
>
> 领域语言见 [`CONTEXT.md`](../../CONTEXT.md)；关键不可逆决策见 [`docs/adr/`](../adr/)。

---

## 1. 概述

### 1.1 目标

- **用户端**：ChatGPT 式对话发起洞察 → Agent 自主选调数据源（搜索/RSS/爬虫）→ 流式回传 → 自动产出**报告 artifact**（markdown + 独立 HTML 网页版本）。
- **管理端**：运行监控、定时任务、数据源管理（启停/标签、RSS 增删）、代理与模型设置。
- **定时洞察**：把一次洞察 prompt + 配置固化为定时任务，到点自动跑全流程并整理报告。

### 1.2 技术栈总览

| 层 | 选型 |
|---|---|
| 前端 | Vue 3 + Vite + TypeScript + TailwindCSS v4 + Vue Router + Pinia（Composition API + `<script setup>`） |
| 后端 | Node.js + TypeScript + Fastify（单进程，承载 API + Agent + cron） |
| Agent | `@earendil-works/pi-coding-agent`（裁剪：禁内置工具、仅 customTools）+ `@earendil-works/pi-ai` |
| 数据源 | 纯 TS：Exa/Firecrawl 官方 SDK + DuckDuckGo(cheerio)、RSS(fast-xml-parser)、爬虫(移植 newsnow) |
| 持久化 | SQLite（better-sqlite3 + WAL + FTS5）+ Drizzle ORM |
| 调度 | node-cron（RSS 轮询 + 定时洞察） |
| 实时 | SSE（EventSource）+ 内存 EventEmitter |
| 代理 | undici ProxyAgent（全局出站） |
| 鉴权 | Bearer Token + SPI（dev 降级） |

> 偏离 `产品原型需求.md`（原为 Next.js 全栈、含 Python 数据源意图）的决定见 [ADR-0001](../adr/0001-stack-vue3-and-independent-backend.md) ~ [ADR-0005](../adr/0005-sqlite-and-drizzle.md)。

## 2. 架构总览

### 2.1 Monorepo 布局（pnpm workspaces + Turborepo）

```
apps/
  web/        用户端 (Vue3 + Vite)        ← 对话式洞察 + 报告浏览
  admin/      管理端 (Vue3 + Vite)        ← 运行/定时/数据源/设置
  server/     Fastify 后端 (单进程)        ← API + Agent 运行 + cron
packages/
  shared-types/   前后端共享 DTO / 枚举
  shared-ui/      Vue 设计系统 (web+admin 共用, 含 EditorialReport 模板)
  api-client/     封装 REST + SSE + TokenProvider (web+admin 共用)
  agent/          Pi SDK 封装 + 洞察流编排  ← 仅 server 依赖
  datasources/    搜索/RSS/爬虫 适配器 + 统一接口 ← 仅 server 依赖
```

依赖方向：`apps/* → packages/{shared-types,shared-ui,api-client}`；`apps/server → packages/{agent,datasources,shared-types}`；`agent → datasources`（工具实现）。

### 2.2 进程拓扑（单进程）

```
┌──────────────────────── Fastify 单进程 ────────────────────────┐
│  REST/SSE API ──┐                                              │
│                 ├─→ Runner（并发上限 3 + 内存队列）            │
│                 │     ├─→ Agent Session (pi-coding-agent)      │
│                 │     │     └ customTools → datasources        │
│                 │     └─→ EventEmitter(runId) ──→ SSE 透传     │
│  node-cron ─────┤                                              │
│   ├ RSS 轮询 (30min) → data_source_items (FTS5)                │
│   └ Schedule 触发 (1min) → 入队 Runner                         │
│  Drizzle → SQLite (WAL)                                        │
│  undici ProxyAgent (全局出站, 可选)                            │
└────────────────────────────────────────────────────────────────┘
        ▲ EventSource(SSE)            ▲ REST
   apps/web (用户端)              apps/admin (管理端)
```

### 2.3 核心运行时序（发起洞察 → 流式 → 报告）

```
用户端                    Fastify                    Agent Session           DataSources
  │  POST /messages ───────→│                            │                       │
  │                         │─ 建 user msg + run(queued)│                       │
  │                         │─ 入队 Runner(并发≤3)       │                       │
  │  GET /runs/:id/stream ←─│                            │                       │
  │   (SSE 打开)            │─ 注水历史 + 新消息 ───────→│                       │
  │                         │  register customTools ────→│                       │
  │                         │  session.subscribe ───────→│                       │
  │                         │                            │─ search/fetch_rss/ ──→│ (代理+时间范围+去重)
  │                         │                            │  crawl/extract        │
  │  ← text_delta/thinking ─│← AgentEvent ───────────────│                       │
  │  ← tool_execution_* ────│                            │                       │
  │                         │                            │─ save_report(...) ──→│
  │                         │← 渲染 EditorialReport →    │   (standalone HTML)   │
  │                         │   存 reports 行            │                       │
  │  ← report_card / done ──│                            │                       │
  │  GET /reports/:id ─────→│                            │                       │
```

## 3. 后端详细设计（`apps/server`）

### 3.1 服务结构

```
apps/server/src/
  main.ts                # 启动：注册 provider/代理/cron/路由，启动时 reconcile interrupted runs
  config/                # env 加载 + 校验
  db/                    # Drizzle schema + better-sqlite3 实例 + 迁移
  plugins/               # Fastify 插件：auth、proxy、error
  routes/                # REST + SSE 端点（见 §6）
  runner/                # 并发受限的 in-process Runner + 事件总线(EventEmitter)
  auth/                  # TokenVerifier SPI + DevTokenVerifier
  jobs/                  # node-cron：rssPoller、scheduleRunner
```

### 3.2 Agent 层（`packages/agent`）

**集成（见 [ADR-0003](../adr/0003-agent-base-pi-coding-agent.md)）**：

```ts
// 伪码
const resourceLoader = new DefaultResourceLoader({
  systemPromptOverride: () => INSIGHT_SYSTEM_PROMPT,
  skillsOverride:        () => ({ skills: [], diagnostics: [] }),
  agentsFilesOverride:   () => ({ agentsFiles: [] }),
  promptsOverride:       () => ({ prompts: [], diagnostics: [] }),
});
await resourceLoader.reload();

const { session } = await createAgentSession({
  model,                          // 内网 provider（见下）
  resourceLoader,
  tools: [],                      // ← 禁用全部内置 read/bash
  customTools: [searchTool, fetchRssTool, crawlTool,
                extractContentTool, listDatasourcesTool, saveReportTool],
  sessionManager:  SessionManager.inMemory(),
  settingsManager: SettingsManager.inMemory(),
});

session.subscribe(ev => bus.emit(runId, ev));   // → SSE
await session.prompt(newUserMessage);
```

**模型 provider**：启动时按 env 注册内网 OpenAI 兼容 provider（`LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`，`api: 'openai'`）。

**Conversation ↔ session**：Conversation = 一个 session；**消息历史以 DB 为唯一真相源**，每轮从 DB 注水历史 + 新消息 → `session.prompt()`。SessionManager 用 `inMemory()`（持久化归 DB 管）。

**自定义工具**（TypeBox 参数；每个工具闭包绑定 `runId` / `conversationId` / 该 Run 的 `config`）：

| 工具 | 入参 | 行为 |
|---|---|---|
| `search` | `{ query, tags?, limit? }` | 扇出启用的搜索引擎（DDG/Exa/Firecrawl）→ 时间范围过滤 → 去重 → 归一化 items |
| `fetch_rss` | `{ keywords?, tags?, limit? }` | 查 `data_source_items`（FTS5 关键词 + 时间范围 + 标签） |
| `crawl` | `{ platforms?, keywords?, limit? }` | 实时拉启用的 newsnow 平台热点 → 过滤/去重 |
| `extract_content` | `{ url }` | 正文提取（Jina → Firecrawl → 本地降级，借 union-search 模式） |
| `list_datasources` | `{ tags? }` | 返回按标签分组的可用源（帮 agent 针对性调用） |
| `save_report` | `{ title, markdown }` | 渲染 `EditorialReport` → standalone HTML；写 `reports` 行；链到 run/conversation |

**System Prompt（`INSIGHT_SYSTEM_PROMPT`）**：情报分析师人设；说明数据源工具用法、时间范围/标签如何取自 Run 配置、Lens 选项；明确**当用户请求洞察/研判/汇总时，综合后调用 `save_report` 交付报告**（过程性文字留在对话，交付物走 `save_report`）。

### 3.3 数据源层（`packages/datasources`，见 [ADR-0004](../adr/0004-datasources-pure-typescript.md)）

**统一抽象**：

- `DataSource`（DB 实体）：`{ id, type: search|rss|crawler, name, tags[], enabled, config(json) }`
  - `search`：3 引擎（duckduckgo/exa/firecrawl）固定存在，**仅启停**，不可删。
  - `rss`：每条 feed URL = 一行，`config={feedUrl}`，**管理员可增删**。
  - `crawler`：每个 newsnow 平台 = 一行，`config={platform}`，**仅启停**。
- `DataSourceItem`（归一化）：`{ sourceType, sourceName, sourceId, title, url, summary, content?, author?, publishedAt, tags[], fetchedAt }`，去重 key = 规范化 URL。

**各源实现**：

| 源 | 模型 | 实现 |
|---|---|---|
| 搜索 | **即时** | Exa / Firecrawl 官方 JS SDK；DuckDuckGo 用 cheerio 抓；扇出 + 时间范围 + 去重 |
| RSS | **后台轮询建索引** | node-cron 周期拉启用 feed → 落 `data_source_items`；`fetch_rss` 查 FTS5 索引（支持「过去 1 个月」） |
| 爬虫 | **即时** | 移植 newsnow TS 适配器；agent 调用时实时拉平台热点列表 |

**去重**：规范化 URL（去 query/fragment/跟踪参数）+ 标题近似；先按 Run 内去重，可扩展全局缓存。

**时间范围**：Run 配置（1d/1w/1m/6m/1y/all）按 `publishedAt` 过滤；能透传给搜索引擎日期过滤的透传。

**代理（见 [§3.6](#36-设置与代理)）**：全部出站走同一 `undici ProxyAgent`。

### 3.4 调度（node-cron）

- **RSS 轮询**（默认每 30min，可配）：拉启用 feed → 写 `data_source_items` + FTS5 索引；保留策略（如 90 天）定期清理。
- **Schedule 触发**（每 1min 扫描）：到期 Schedule → 用其 `prompt + config + lens` 创建一次 Insight Run → 入队 Runner → 产出 Report（in-app 可见）。
- **启动 reconcile**：把 `running` 的 run 标记 `interrupted`。

### 3.5 持久化（Drizzle schema，见 [ADR-0005](../adr/0005-sqlite-and-drizzle.md)）

```
users            { id, role(user|admin), externalId?, ... }
conversations    { id, userId, title, config(timeRange, lens?), createdAt }
messages         { id, conversationId, role(user|assistant|tool), content(json),
                   toolCall?, runId?, createdAt }              ← 对话历史(真相源)
insight_runs     { id, conversationId, triggerMsgId, status(queued|running|
                   completed|failed|interrupted), lens?, startedAt, endedAt,
                   tokens, reportId? }
reports          { id, runId, conversationId, title, markdown, html(standalone), createdAt }
data_sources     { id, type, name, tags[], enabled, config(json), createdAt }
data_source_items{ id, sourceType, sourceName, sourceId, title, url, summary,
                   content, author, publishedAt, tags[], fetchedAt }   ← + FTS5 虚表
schedules        { id, userId, prompt, config(json), cron, lens?, enabled,
                   lastRunAt, nextRunAt, createdAt }
settings         { key, value }   ← proxy / llm / rssCadence 等
```

### 3.6 设置与代理

- `settings` 表存管理端配置：`proxy`（host/port/认证）、`llm`（provider/模型，可覆盖 env）、`rssCadence` 等。
- 启动时若有 proxy，建 `undici ProxyAgent` 设为全局 dispatcher，套到全部 search/RSS/crawler/`extract_content` 出站；数据源层不感知代理。

### 3.7 鉴权（SPI + dev 降级）

- Header：`Authorization: Bearer <token>`。
- 后端 `TokenVerifier` 接口：`verify(token) → { userId, role }`。`DevTokenVerifier`（dev）：decode JWT 不验签 / 共享 secret 签发。prod：留给内网 JWT 校验实现。
- 前端 `TokenProvider` 接口（`packages/api-client`）：`getToken()`。dev：最简 dev 登录拿 token 存 localStorage；prod：内网 SSO 实现插入。

## 4. 前端详细设计

> 遵循 `vue-best-practices`：Composition API + `<script setup lang="ts">`；route view 保持薄（仅编排）；feature 拆为子组件 + composable；props down / events up；`v-model` 仅用于真正双向契约。

### 4.1 用户端（`apps/web`）

**路由**：`/c/:id`（对话）· `/reports` · `/reports/:id`（报告查看）· `/schedules`。

**布局**：左侧栏（会话列表 + 新建 + 我的定时 + 报告入口）+ 主区；对话顶部 `ConfigBar`（时间窗 + 标签偏好，Conversation 级）。

**对话特性组件边界**（`views/ConversationView.vue` 薄编排）：

- `components/conversation/`：`MessageList` · `MessageItem` · `ToolCallCard` · `ReportCard` · `ChatInput` · `ConfigBar`
- `components/report/`：`EditorialReport`（HTML 报告模板，web 查看页 + 服务端 standalone 渲染复用）· `MarkdownReport` · `ExportBar`（下载 standalone HTML）
- `composables/`：`useInsightRun`（订阅 SSE，把 Pi `AgentEvent` → 响应式状态：文本缓冲、thinking、工具卡、报告）· `useConversations` · `useAuth`

**流式**：`useInsightRun(runId)` 开 `EventSource('/api/runs/:id/stream')`，映射事件增量渲染 assistant 文本 / thinking / 工具卡；`save_report` 触发 `ReportCard`；支持自动重连。

**报告查看**：`/reports/:id` 内 `EditorialReport` 渲染 HTML 报告（editorial 版式）+ markdown 切换；`ExportBar` 下载 standalone HTML。v1 不做 PDF。

### 4.2 管理端（`apps/admin`）

**路由**：`/runs`（运行监控：running/排队/历史 + 实时状态）· `/schedules` · `/datasources`（启停/标签/RSS 增删）· `/settings`（代理 + 模型 + JWT prod 入口）。标准 CRUD dashboard，复用 `shared-ui`。

### 4.3 共享设计系统（`packages/shared-ui`）

editorial 设计语言（源自 `ref/v2-editorial.html`）：色板（paper/ink/vermillion/mustard/forest/cobalt/rose）、字体（Fraunces 衬线 + Inter Tight + JetBrains Mono）、版式构件（报头、drop-cap、By the Numbers、热度条、供稿榜、双线/印章）。提供 `EditorialReport` 模板组件 + 基础组件（`BaseButton`/`Tag`/`DataTable` 等）。

### 4.4 HTML 报告 standalone 渲染

服务端用 `@vue/server-renderer` 的 `renderToString(EditorialReport, { props })` 生成 HTML，内联 CSS（Tailwind 构建产物 + editorial 自定义），写入 `reports.html`。该字符串可：在 app 内查看、作为独立 .html 下载/分享。前端查看页复用同一 `EditorialReport` 组件（客户端渲染）。

## 5. API 设计（REST + SSE）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/dev-login` | dev 登录拿 token |
| GET/POST/PATCH/DELETE | `/api/conversations[/:id]` | 会话 CRUD（PATCH 改 config/title） |
| GET | `/api/conversations/:id` | 含 messages 历史 |
| POST | `/api/conversations/:id/messages` | 发用户消息 → 触发 Run |
| GET | `/api/runs/:id` | Run 状态 |
| GET | `/api/runs/:id/stream` | **SSE** 事件流（AgentEvent 透传） |
| POST | `/api/runs/:id/abort` | 中止运行 |
| GET | `/api/reports[/:id]` | 报告列表 / 详情（markdown+html） |
| GET | `/api/reports/:id/html` | standalone HTML |
| GET/POST/PATCH/DELETE | `/api/schedules[/:id]` | 用户定时任务 |
| GET/PATCH | `/api/datasources[/:id]` | 数据源（PATCH 改 enabled/tags） |
| POST/DELETE | `/api/datasources` | **仅 RSS** 增删 |
| GET | `/api/admin/runs` | 全量运行监控（admin） |
| GET/PUT | `/api/admin/settings` | 代理/模型等设置（admin） |

## 7. 实现路线

1. **骨架**：monorepo（pnpm + turbo）+ 6 个 package/app 初始化；Drizzle schema + SQLite；Fastify 最小路由 + 鉴权 SPI（dev）。
2. **【优先 spike】coding-agent headless 验证**：确认 `createAgentSession` 禁内置工具、无工作区、内网 provider、`session.subscribe` 事件齐全；若需 cwd 指空临时目录。（见 [ADR-0003](../adr/0003-agent-base-pi-coding-agent.md) 风险项）
3. **数据源层**：搜索（3 引擎）+ RSS 轮询建索引 + 爬虫（移植 newsnow）+ 去重 + 代理出口。
4. **Agent + Runner + SSE**：customTools 接 datasources、`save_report`、并发受限 Runner、事件总线、SSE 透传。
5. **报告渲染**：`EditorialReport` 模板 + 服务端 standalone HTML 渲染。
6. **前端 web**：对话流式 UI + 报告查看（editorial）+ schedules。
7. **前端 admin**：runs/schedules/datasources/settings。
8. **调度**：RSS poller + Schedule 触发 + 启动 reconcile。
